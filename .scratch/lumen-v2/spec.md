## 1. Product

lumen v2 is an **AXI CLI** (consumed primarily by an AI agent) for managing **birth profiles**. The human talks to an agent and gives the city + country and local birth date/time; the agent resolves lat/lon and UTC offset and calls lumen; lumen validates, computes the Julian Day and persists. lumen never resolves world facts: it is the deterministic interface.

**Pivot (out of scope, does not return):** all astrology (chart, evo, journey, karma, draconic, projection…), geocoding, timezone resolution, v1 data migration (`~/.config/lumen/`), config store, non-profile commands.

## 2. Data model

```
Profile {
  id: UUID            // auto-generated by lumen, unique and opaque
  name?: string       // optional, descriptive, no uniqueness or lookup
  birthPlace: string  // required, human-readable (e.g. "Madrid, Spain"); CLI flag --birthplace
  birthDateTime: string // required, ISO 8601 with UTC offset (the --birthdatetime value)
  birthLat: number    // required, −90..90 (--birthlat)
  birthLon: number    // required, −180..180 (--birthlon)
  birthJdUt: number   // derived: Meeus ch. 7 (via julianDayUt)
}
```

Flat `birth*` vocabulary (ADR-0005): every birth field carries its identity in
the `birth` prefix, across the CLI flag, the model field and the stored column.
No `status` / `zone` / `dst` (no timezone resolution). The civil time and the
UTC offset are not stored separately — they arrive and are stored as the single
`birthDateTime` ISO value.

## 3. CLI contract

```
lumen profile add --birthdatetime "YYYY-MM-DDTHH:MM±HH:MM" --birthlat <lat> --birthlon <lon> --birthplace "<human-readable place>" [--name <slug>]
lumen profile list
lumen profile get <uuid>
lumen profile delete <uuid>
```

Rules:

- `add` **deduplicates on the birth**: if a profile with the same
  `birthJdUt + birthLat + birthLon` already exists, it is returned (the
  `name`/`birthPlace` of the second `add` are discarded — the birth is the
  identity).
- `--birthdatetime` is an **ISO 8601 datetime with an explicit UTC offset**:
  `YYYY-MM-DDTHH:MM±HH:MM` or `…Z` (offset zero). No separate `--offset` flag —
  the offset rides inside `--birthdatetime`, resolved by the agent, never by
  lumen. Coordinates are two flags, `--birthlat` / `--birthlon` (signed decimal
  degrees).
- `get`/`delete` by **UUID only** (no lookup by name or birthPlace).
- Validation (the violated rule is cited in the error): offset −840..+840 minutes
  (`±HH:MM`); year 1800–2100; month 1–12; day valid by pure arithmetic
  (Gregorian leap rule); hour 0–23; minute 0–59; birthlat −90..90;
  birthlon −180..180.
- AXI errors: `VALIDATION_ERROR` (input), `NOT_FOUND` (`get`/`delete` of an
  unknown UUID), `PROFILE_ERROR` (store failure, e.g. unwritable cwd).
- Messages in **English**.
- **TOON-only** output (no `--json`): centralized policy in `toon.ts` —
  `birthJdUt` at 6 decimals, `birthLat`/`birthLon` at 4, `birthDateTime` echoed
  as stored; display only (the DB keeps full precision). The agent parses the
  text.

## 4. Julian Day computation

Formula **Meeus, *Astronomical Algorithms* ch. 7** in pure arithmetic (no dependencies, no DST table) — bit-identical to caelus’s `julianDay` (verified: 14/14 vectors, 0 mismatches over 1800–2100). Reference: `research/calculo-jd-y-deps.md`.

## 5. Persistence

- File: `./lumen.db` in the cwd (per-project); `LUMEN_DB` env override (full file path).
- **Lazy creation**: only `add` creates the file (and its directory); `list`/`get`/`delete` against a missing DB respond empty/not-found without creating files.
- **0600** permissions, **rollback** journal (no WAL), migrations via **PRAGMA user_version** (starts at 1; current schema v4).

```sql
CREATE TABLE IF NOT EXISTS profiles (
  id              TEXT    PRIMARY KEY,
  name            TEXT,
  birth_place     TEXT    NOT NULL,
  birth_date_time TEXT    NOT NULL,   -- ISO 8601 with UTC offset
  birth_lat       REAL    NOT NULL,
  birth_lon       REAL    NOT NULL,
  birth_jd_ut     REAL    NOT NULL,
  created_at      TEXT    NOT NULL,
  updated_at      TEXT    NOT NULL
);

-- Birth dedupe: one profile per (birthJdUt, birthLat, birthLon)
CREATE UNIQUE INDEX idx_profiles_birth ON profiles (birth_jd_ut, birth_lat, birth_lon);
```

v3→v4 migration (2026-08-18): the columns are renamed to the flat `birth_*`
names (`birthplace`→`birth_place`, `"when"`→`birth_date_time`, `lat`→`birth_lat`,
`lon`→`birth_lon`, `jd_ut`→`birth_jd_ut`); the unique birth index follows the
renames. Every pre-v4 db (v1/v2 converge through the ADR-0004 `when` collapse)
converges to the `birth_*` set — which also drops the `when` SQL reserved-word
quoting.

## 7. Tests (`bun test`)

- `tests/args.test.ts` — the CLI-args contract: flag forms, duplicates, missing
  values, required flags, positional counts, value rules, `--help`, accumulated
  errors.
- `tests/birth-input.test.ts` — `--birthdatetime` ISO formats (`±HH:MM`, `Z`,
  invalid forms, missing offset) + semantic ranges; `--birthlat`/`--birthlon`;
  accumulation.
- `tests/jd.test.ts` — the 14 reference vectors (research 02); boundary validations (Feb 30, hour 24, offset ±841, year 1799/2101, lat ±90.1, lon ±180.1); offset round-trip.
- `tests/profile-store.test.ts` — CRUD; dedupe (ON CONFLICT returns the existing profile); lazy creation (`list` does not create the file, `add` does); 0600 permissions; `LUMEN_DB` override; `user_version` migration (v1→v4, v2→v4, v3→v4).
- `tests/cli.test.ts` — input contract (each flag + combinations); AXI errors; TOON output (rounding applied, `birthDateTime` echoed); `add` prints the UUID; dedupe visible from the CLI.
